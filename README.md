# أثري | ملف إنجازي الرقمي

**الموقع المباشر:** https://circonet24-ux.github.io/my-portfolio/

تطبيق ويب عربي (RTL) لتوثيق الإنجازات المهنية والشواهد والتقارير في ملف رقمي واحد، بواجهة عصرية ووضعين نهاري وليلي.

## المزايا

- حساب سحابي لكل مستخدم عبر Supabase Auth، مع عزل كامل للبيانات باستخدام Row Level Security.
- ملف مهني قابل للتعديل، وإنجازات وشواهد وتقارير مع البحث والتصفية.
- إرفاق الصور والمستندات والروابط، مع ضغط الصور تلقائيًا قبل الحفظ.
- مزامنة تلقائية بين الأجهزة عند الدخول بالحساب نفسه.
- نسخ احتياطي واستيراد بصيغة JSON.
- تصميم متجاوب يعمل على الحاسوب والجوال، ودعم الطباعة.

## كيف يعمل التطبيق؟

- الواجهة ثابتة داخل مجلد `public/` وتُستضاف على GitHub Pages.
- المصادقة وتخزين البيانات يتمّان عبر Supabase.
- الجداول الأساسية:
  - `profiles`: الملف المهني.
  - `items`: الإنجازات والشواهد والتقارير.
  - `activity`: سجل النشاط.
- جميع الجداول محمية بـ RLS، ولا يستطيع أي مستخدم قراءة أو تعديل بيانات مستخدم آخر.
- دالة `replace_workspace` تستبدل بيانات المستخدم بالكامل عند استيراد نسخة احتياطية.

## إعداد Supabase (خطوة بخطوة)

### 1. إنشاء المشروع

1. افتح https://supabase.com/dashboard.
2. أنشئ مشروعًا جديدًا، واحتفظ باسم المشروع وكلمة مرور قاعدة البيانات.
3. انتظر حتى يكتمل تجهيز المشروع.

### 2. تنفيذ مخطط قاعدة البيانات

1. من لوحة المشروع افتح **SQL Editor**.
2. اضغط **New query**.
3. انسخ كامل محتوى الملف `supabase/schema.sql`.
4. الصقه ثم اضغط **Run**.
5. تأكد من ظهور رسالة نجاح دون أخطاء.

هذا الملف ينشئ الجداول، والفهارس، والمشغلات، وسياسات RLS، ودالة `replace_workspace`.

### 3. نسخ مفاتيح المشروع

1. افتح **Project Settings** ثم **API**.
2. انسخ:
   - **Project URL**
   - **anon public** key (أو **publishable** key في المشاريع الحديثة)
3. افتح ملف `public/supabase-config.js` وضعهما هكذا:

```js
window.ATHARI_SUPABASE = {
  url: 'https://xxxxxxxx.supabase.co',
  anonKey: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9....'
};
```

> **مهم:** استخدم `anon public` فقط. لا تضع `service_role` أو أي مفتاح سري في هذا الملف أو في أي ملف داخل `public/` أو في Git. مفتاح `service_role` يتجاوز RLS ويسرّب كل البيانات.

يوجد قالب جاهز في `public/supabase-config.example.js` يمكن نسخه عند الحاجة.

### 4. ضبط روابط المصادقة

من **Authentication → URL Configuration**:

- **Site URL:** `https://circonet24-ux.github.io/my-portfolio/`
- **Redirect URLs:** أضف:
  - `https://circonet24-ux.github.io/my-portfolio/`
  - `http://127.0.0.1:3000/` (للتشغيل المحلي)

إذا فعّلت **Confirm email**، فسيصل رابط تأكيد إلى بريد المستخدم قبل أول دخول. يمكنك تعطيله من **Authentication → Providers → Email** أثناء التجربة.

### 5. تشغيل الموقع محليًا

يتطلب المشروع Node.js 24 أو أحدث:

```bash
npm start
```

ثم افتح: `http://127.0.0.1:3000`

> خادم `server.js` مخصص للمعاينة المحلية فقط. الموقع نفسه ثابت بالكامل داخل `public/`، والبيانات تُحفظ في Supabase.

## النشر على GitHub Pages

الموقع منشور من الفرع `gh-pages`، الذي يحتوي على محتويات مجلد `public/` في جذر الفرع. يبقى الفرع `main` مخصصًا لملفات المصدر والتطوير.

لإعادة نشر نسخة محدثة بعد تعديل `public/`:

```bash
git subtree split --prefix=public -b gh-pages-deploy
git push origin gh-pages-deploy:gh-pages --force
git branch -D gh-pages-deploy
```

ثم تأكد من أن إعداد **Pages** في المستودع يستخدم الفرع `gh-pages` والمجلد `/ (root)`.

## نقل البيانات القديمة من localStorage

النسخة القديمة كانت تحفظ البيانات محليًا. لا يتم نقلها تلقائيًا إلى Supabase. لنقلها:

1. افتح النسخة القديمة من الموقع قبل نشر النسخة الجديدة.
2. من **الإعدادات → النسخ الاحتياطي** اضغط **تصدير نسخة**.
3. افتح النسخة الجديدة وسجّل الدخول.
4. من **الإعدادات → النسخ الاحتياطي** اضغط **استيراد نسخة** واختر ملف JSON.

الاستيراد يستبدل محتوى الحساب الحالي بالكامل، لذا صدّر نسخة من البيانات الحالية أولًا إن كنت تحتاجها.

## الأمان والخصوصية

- كلمات المرور تديرها Supabase Auth ولا تمر عبر قاعدة البيانات أو الواجهة كنص صريح.
- كل صف في `profiles` و`items` و`activity` مرتبط بـ `auth.uid()`، وسياسات RLS تمنع الوصول إلى بيانات الآخرين.
- مفتاح `anon` عام بطبيعته، لكنه لا يمنح وصولًا إلا وفق سياسات RLS.
- لا تُرفع ملفات `.env` أو المفاتيح السرية؛ ملف `.gitignore` يستثني ملفات `service-role` و`service_role`.
- رمز جلسة الدخول يُخزَّن محليًا تحت المفتاح `athari.supabase.auth` لتسهيل البقاء مسجلًا، بينما تُحفظ بيانات الملف في Postgres.
- يُنصح بتصدير نسخة احتياطية دوريًا.

## استكشاف الأخطاء

| المشكلة | الحل |
| --- | --- |
| تظهر رسالة «لم تُضبط إعدادات Supabase» | املأ `public/supabase-config.js` بقيم Project URL و anon key. |
| تظهر رسالة «جداول Supabase غير موجودة» | نفّذ `supabase/schema.sql` كاملًا من SQL Editor. |
| تظهر رسالة «دالة replace_workspace غير موجودة» | أعد تنفيذ القسم الأخير من `schema.sql` أو الملف كاملًا. |
| تعذّر تسجيل الدخول | تأكد من تأكيد البريد إن كان مفعّلًا، ومن صحة كلمة المرور. |
| لا تظهر البيانات بعد الدخول | تحقق من سياسات RLS ومن أن المستخدم يملك صفوفًا في الجداول. |
| فشل الاستيراد | تأكد من أن الملف نسخة JSON صالحة، ومن أن حجمه أقل من 12 م.ب. |
